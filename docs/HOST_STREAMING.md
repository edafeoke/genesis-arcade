# Playable casual multiplayer

Genesis Arcade now provides **host-authoritative streaming**, alongside the separate deterministic-netplay research. One browser runs the pinned Genesis emulator. Its canvas and Web Audio output are streamed to the guest using WebRTC. The guest's sequenced complete controller masks arrive on a reliable, ordered data channel and are applied only to the other Genesis controller port. This avoids two independently running cores drifting apart. It is not rollback, deterministic input lockstep, or competitive netplay.

## Two browsers on one computer

The configured local frontend is http://127.0.0.1:3100 and the separate room service listens on loopback port 4001.

1. Open the app in two independent tabs or browsers. Use a new tab rather than Duplicate Tab, which can clone the private session credential.
2. In **Play online**, add the free **Quickdraw Duel** demo in each browser, or import your own matching two-player Genesis game.
3. Connect both clients. Create a private room in the first client, join its code in the second. Public lobby rooms use the same gameplay path.
4. Select the same local game and confirm its two-player mode in both clients. Mark both Ready.
5. The host selects **Start Game**, then **Start game** inside the emulator. The guest receives the picture and can select **Enable sound** after an audio track arrives.
6. For one keyboard on this computer, the host selects **Shared keyboard for both players** under Input device. Keep that host window focused. The guest continues to display the same game. Normal remote mode gives each browser its own controller; select different gamepad numbers when using two pads on the same computer.

| Shared keyboard | Player 1 | Player 2 |
|---|---|---|
| Direction | Arrow keys | W/A/S/D |
| A / B / C | J / K / L | F / G / H |
| X / Y / Z | U / I / O | R / T / Y |
| Start | Enter | Space |
| Mode | Right Shift | Left Shift |

Shared-keyboard mode is explicit: the host owns both keyboard ports and guest input cannot overwrite the second port. Switch back to Keyboard only or a gamepad option to restore remote controller ownership. Controller-slot swaps remain available before starting.

**Quickdraw Duel** is an original CC0 Genesis homebrew generated by `node scripts/build-quickdraw.mjs`. Press Start, wait for green, then press B first. Early presses lose. Simultaneous presses in the same emulated frame tie. Start begins a rematch. Source, bitmap glyphs and ROM are included; no third-party ROM content is distributed. See `public/demos/LICENSE.txt`.

## Start the services

```sh
pnpm build:webpack
pnpm server:build
pnpm start --port 3100
# Another terminal:
pnpm server:start
```

For development: `pnpm dev` and `pnpm server:dev`. Builds/dev prepare the isolated online bridge automatically. Offline single-player still uses `/player/index.html`, independently of sockets, peers or an internet connection. Online runtime assets live under `/online-player/` and are excluded from the offline package so an old service worker cannot freeze its session protocol. Previously downloaded offline packages should be refreshed after an app update.

## Session and security boundaries

- Room membership, connected/readied players, exact ROM SHA-256/profile agreement, host start permissions, slot assignments and a new UUID epoch are enforced by the server.
- `stream:start`, `stream:signal` and `stream:stop` are separate from the still-gated deterministic `room:start`. `syncAvailable:false` continues to mean deterministic netplay is unavailable. `streamAvailable` advertises the separately enabled mode.
- The room service relays only bounded, strict SDP/ICE signaling to the other active room member. Host offers/guest answers are role checked. No ROM, save state, media or controller stream goes through the room server. WebRTC transports encrypted media and input between peers; a configured TURN relay may carry encrypted peer traffic on other networks.
- Ordinary room packets retain their 4096-byte application limit. The engine ceiling is 32768 bytes for SDP, with a 24000-character SDP bound and separate signaling quotas (100/socket and 400/IP per 10 seconds). Ordinary quotas are unchanged. Unknown fields, stale epochs and outsider signaling are rejected.
- Input packets are capped at 256 characters and 180 per second. Monotonic sequence numbers suppress stale/duplicate packets. No packet can choose a player slot or invoke emulator hotkeys. Full masks include releases. Blur/visibility changes release local input. A missing heartbeat releases held remote buttons after 750 ms; a dead connection closes the session. Data-channel queues are bounded.
- Ending, leaving, disconnecting, or replacing a room connection terminates the active epoch and clears readiness. Reconnection restores the waiting-room slot where permitted; gameplay starts fresh, with no claim of in-game state recovery. Save important progress before ending the host emulator.
- Only keyboard/controller events and the emulator's own canvas/audio are used. No microphone, camera, desktop capture or screen-sharing permission is requested.
- Active-room pings maintain idle activity; the two-hour room lifetime still applies. `MULTIPLAYER_STREAMING=false` disables new streaming sessions.

The media implementation follows the browser's [canvas capture API](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/captureStream), [WebRTC media tracks](https://developer.mozilla.org/en-US/docs/Web/API/RTCPeerConnection/addTrack), and [ordered data channels](https://developer.mozilla.org/en-US/docs/Web/API/RTCDataChannel/ordered).

## Other computers and networks

The requested two-browser localhost setup needs no public deployment or TURN service. For another device, use HTTPS/WSS with configured frontend origins and a reachable service URL. Other networks often need a TURN relay; configure build-time `NEXT_PUBLIC_RTC_ICE_SERVERS` as a JSON array of RTCIceServer objects. Default discovery uses public STUN. No public internet/device compatibility claim follows from the local two-client test.

The frontend defaults to port 4001 on localhost; production non-localhost defaults to same-origin signaling through a reverse proxy unless `NEXT_PUBLIC_MULTIPLAYER_URL` is set. Deploy the room service with an exact HTTPS origin allowlist. Don't expose the local loopback configuration as a production deployment.

## Validation

- Automated tests cover room/start/slot/epoch authority, active-peer-only signaling, malformed and ROM-bearing messages, bounded signaling, disconnect teardown, remote controller isolation, full-mask releases, stale/duplicate inputs, missing heartbeats, spoofed slot fields, parent-origin checks and shared-keyboard ownership.
- Browser checks use an original two-controller fixture and Quickdraw Duel, not a commercial ROM. They verify received video, local and remote controller response, a completed Player 2 win, rematches, and returning both clients to the room. Physical gamepads and separate-device networks require their own checks.

### Recorded local result

`host-streaming-browser-proof.json` records the local check. `host-streaming-proof.png` and `host-streaming-guest-proof.png` show the connected game. Both shared-keyboard players completed wins, Player 2 started a rematch, and the guest received video plus an audio track (playback ready state 4, decoded video 562×442). All 64 automated checks pass; lint, TypeScript, server compilation and the webpack production build pass. Short presses are retained until the host observes a core frame advance, so a press/release between two ticks is sampled once; blur, disconnect and teardown bypass that latch to release controls immediately.
